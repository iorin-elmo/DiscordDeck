# DiscordDeck

複数のDiscordアカウントを、ひとつのWindowsアプリで並べて使う試作アプリです。公式Web版をElectronの独立したブラウザセッションで開きます。

## 起動

`dist/DiscordDeck-0.7.1-portable.exe` をダブルクリックしてください。インストールは不要です。旧バージョンが開いている場合は、ウィンドウ右上の×で終了してから新しいexeを起動してください。未署名のため、Windowsが発行元を確認できない旨を表示する場合があります。

0.7.1では、指定画像を実行ファイル・ウィンドウ・アプリ内のロゴに設定しました。フルスクリーンモードとログイン保持の対策も含まれています。

単体テスト36件とブラウザテスト18件で検証しています。開発版Electronの自動起動にはDevice Guardの制限があるため、テスト用画面とAPI代替による検証です。ネイティブの全画面描画、実アカウントの更新後のログイン保持、通話・実機の入出力切り替えは未検証です。詳細は [検証結果](VALIDATION.md) を参照してください。

開発版は、このフォルダの `Start-DiscordDeck.cmd` をダブルクリックするか、PowerShellで次を実行します。

```powershell
cd C:\Users\iorin\Desktop\develop\DiscordDeck
npm.cmd install
npm.cmd start
```

開発版にはNode.js 22以上が必要です。完成したexeの起動にはNode.jsは不要です。

## 使い方

1. 「アカウントを追加」を押し、「仕事用」などの表示名を入力します。
2. 列内のDiscord公式ログイン画面でログインします。認証情報はDiscordの画面にのみ入力します。
3. 別のアカウント用にもう一つ列を追加し、そのアカウントでログインします。同じアカウントを複数の列で開くこともできます。
4. 左バー下部で2列・3列・4分割を切り替えます。各列の拡大アイコンで単独表示と解除を切り替えます。
5. 列の右上の「…」から、表示名・色・ミュート・デスクトップ通知・アイコン・マイク・カメラを設定できます。表示倍率もこの画面の「−」「+」で50〜125%に調整します。倍率は即時保存されます。カラーコードは `#RRGGBB` または `#RGB` を指定でき、色は「変更を保存」で反映します。
6. 左バーのアイコンをドラッグすると表示順が変わります。列の設定の「上に移動」「下に移動」、または左バーにフォーカスしてAlt+↑/↓でも移動できます。並び順を変えてもログイン状態は維持します。
7. アイコンは、公式画面の現在ユーザー欄から取得した画像を既定値にします。「画像を選ぶ」から好きな画像に変え、「Discordのアイコンに戻す」で自動表示に戻せます。カスタム画像は中央を正方形に切り抜き128pxのPNGとして保存します。入力画像は10MB以下にしてください。
8. 音声通話はDiscord内の通話ボタンから開始し、マイクの確認で「許可する」を選んでください。ビデオ通話は列の設定でカメラも有効にしてから許可します。許可はアカウント・機器の種類ごとに確認し、アプリを終了するまで記憶します。許可設定をオフにすると列を再読み込みして通話を終了します。
9. カラム左上の三本線からサーバーメニューを開きます。メールアイコンはDM一覧への入口です。個々のフレンドはこのメニューに表示しません。サーバーの検索やフォルダの展開ができます。移動先はDiscordが現在描画している一覧から取得します。仮想スクロールで未描画の移動先がある場合や、サーバー追加・探索などを使う場合は「Discordの元の一覧・上部バーを表示」を押してください。名前を取得できない項目はIDを出さず「名前を取得できないサーバー」と表示します。
10. 「…」の「Discordの上部バーをまとめる」「サーバー一覧をメニューにまとめる」で統合表示を切り替えられます。既定は有効ですが、対応するバーと移動操作を検出できた場合だけ隠します。メニュー操作で移動先を確認できなかった場合も元の一覧を復元します。ログイン画面は隠しません。

0.4.0への初回更新時は、以前の自動復元で無効になった列も含め「サーバー一覧をメニューにまとめる」を一度だけ有効にします。その後に手動で無効にした設定は保持します。

外部リンクの確認で「次回からは表示しない」をチェックして「開く」を選ぶと、開く処理が成功した場合だけ、対象アプリへの許可を保存します。同じブラウザを使うHTTPとHTTPSのリンクは共通の許可になります。既定のアプリが変わった場合や、別アプリを使う場合は再確認します。「使い方」の「外部アプリの許可をリセット」で許可を消せます。Windowsの関連付けからアプリを識別できない場合は、記憶せず毎回確認します。

最大8列を登録できます。現在の表示数を超える列は、左のアカウントボタンまたは左バー下部の矢印で切り替えます。画面が低い場合はアカウント一覧をスクロールできます。非表示の列もページは動作し続けます。PCのメモリ使用量は列数に応じて増えます。

左バーの赤いマークは、公式画面のタイトルやサーバー一覧の未読表示に連動します。数字が得られる場合は件数、その他の未読は点を表示します。OS通知を許可しなくても動作し、列を選んだだけでは消しません。Discord側で既読になったときに消えます。これは公式画面に見える未読の目印であり、全メッセージの件数やOS通知履歴を示すものではありません。アイコン・未読の取得はDiscordの画面構造に依存するため、Discord側の変更で取得できなくなる場合があります。アイコンを取得できないときは表示名の先頭2文字を使います。

ログイン状態と、最後に開いたDM・チャンネルのURLは次回起動時に引き継ぎます。列を消すと、その列の保存済みログイン情報・キャッシュも消します。Discordアカウント自体は削除しません。Discord側でログアウトした場合やセッションが失効した場合は再ログインが必要です。

## 対応範囲

- Discord公式Web版の表示、メッセージの閲覧・手動送信を目的とした試作です。
- 音声・ビデオ通話のためのマイク・カメラ許可を実装しています。実際の通話は未検証です。Windows側のデスクトップアプリへのアクセス許可、Discord内の入力・出力デバイス設定も必要です。列をミュートすると通話相手の声も聞こえなくなるので、通話する列はミュートを解除してください。画面共有は未対応です。
- デスクトップ通知は初期状態では無効です。列の設定で許可し、Discord側とWindows側の通知設定も確認してください。実アカウントでの通知受信は未検証です。
- 添付ファイルのダウンロードは保存ダイアログを表示します。外部リンクは確認後に既定のブラウザ等で開きます。リンク先にDiscordDeckのログイン状態は引き継ぎません。
- Discord公式アプリの一部の機能や、外部サービスのポップアップ認証は動作しない場合があります。
- メッセージをアプリ独自の統合タイムラインに集約する機能はありません。列の中は公式Web版の画面です。

## 保存場所と設計

設定は `%APPDATA%\DiscordDeck\deck.json`、ログイン状態は同フォルダ内の `Partitions` に保存します。portable.exeでもデータはexeの隣ではなく、このフォルダに保存されます。開発版とexeは同じ保存先を使います。

表示名はアプリ内のラベルです。Discord側の隔離preloadで、現在ユーザー欄の画像、上部バーのタイトル、一覧のサーバー・DM名、未読目印を読み取ります。0.3.0からは統合表示用のCSSを適用し、利用者がメニューで選んだ移動先に対応する元のナビゲーション要素をクリックします。メッセージ本文・認証情報・内部ストアは読み取らず、独自APIからのメッセージ取得、トークン抽出、バックグラウンドでの操作の自動化は行いません。ログイン用Cookie等はChromiumが管理するため、保存フォルダを他人に渡したり、Gitに追加したりしないでください。

名前を取得できないサーバーがある場合だけ、`%APPDATA%\DiscordDeck\server-name-diagnostics-<列ID>.json` に対象要素と親子要素の限定属性を保存します。対象はサーバー一覧内のクラス名・role・名前用属性等だけで、HTML全体・メッセージ本文・認証情報は保存しません。外部への送信は行いません。この診断は取得できない構造を調べるためのものです。

アカウントごとに `persist:discorddeck-<UUID>` を割り当て、Cookie・Local Storage等を分離しています。Discordの各WebContentsViewはNode.js無効・サンドボックス有効・contextIsolation有効で、管理画面用のIPCブリッジは渡しません。管理操作はローカル画面のメインフレームからのみ受け付けます。preloadからの通知は対応するDiscordメインフレームの送信元を検証し、移動先は取得済みの限定キーから選びます。任意のURLやスクリプトを実行する機能は公開しません。アイコンURLはDiscordの画像ドメインと画像パスに制限します。Webセキュリティや証明書検証を無効化していません。

通常ユーザーの自動操作（self-bot）は[Discordで禁止されています](https://support.discord.com/hc/en-us/articles/115002192352-Automated-User-Accounts-Self-Bots)。また、Discordは[クライアントの改変を禁止しています](https://discord.com/safety/platform-manipulation-policy-explainer)。本アプリの統合表示は公式Web版に独自CSSを適用する非公式の機能です。Discordが認定・承認した製品ではなく、規約適合性を保証するものではありません。公開・配布する場合は、その時点の規約と運営側の見解を確認してください。Discord側の仕様や認証制限によって動作しなくなる可能性があります。

## 更新時のログイン保持（0.6.1）

設定とブラウザデータの保存先をともに `%APPDATA%\DiscordDeck` に明示し、既存の列IDと `persist:discorddeck-<UUID>` を継続して使用します。exeのファイル名・バージョン・一時展開先には依存しません。ログイン情報の読み取り・コピーや、再ログインの自動化は行いません。

Electronの標準User-Agentにはアプリの版番号が含まれます。0.6.1からはDiscordDeckの版番号だけを識別文字列から外し、実際のChromium/Electronの情報を残します。終了時は列を破棄する前にDOMStorageの保存を要求し、全セッションのCookieのディスク書き込みを待ってから終了します。ページの読み込み・画面内移動・Cookie更新後にも保存を要求します。

「カラムは残り、新しい版の初回だけDiscordがログアウトする」という報告への対策です。識別文字列の変化がDiscord側のログアウト判定の原因だったかは未確定です。この修正版への最初の切り替えでは識別文字列が変わるため、再ログインが必要な場合があります。Discord側で認証が失効した場合、または強制終了・OS障害などで保存できなかった場合の保持は保証できません。

## 本体設定（0.6.0）

左下の「？」の上にある歯車から、全アカウント共通の設定を変更できます。

- フルスクリーン（0.7.0）：チェックを変更して「設定を保存」を押すと、タイトルバーを隠した全画面表示に切り替えます。F11では即座にオン・オフを切り替えられ、Discord側にフォーカスがある場合も使用できます。設定を次回起動時にも復元し、解除時は通常のウィンドウサイズへ戻ります。EscはDiscordの操作・ダイアログを閉じるために残し、全画面解除はF11または本体設定で行います。全画面中もAlt+F4でアプリを終了できます。
- 通知音：Discordの通知・着信・操作用の静的音声を消音します。通話音声と添付ファイルの音声は残します。アカウントの「音声をミュート」は従来どおり通話を含む全音声が対象です。
- 秘匿表示：フォーカスが外れるとネイティブのDiscord画面を隠し、管理画面・アカウント名・開いている設定も覆います。フォーカスを戻すと復帰します。通話と通知音は継続します。ページから作成するOS通知も内容を伏せ、表示中の通知を閉じます。録音停止や画面共有停止を行う機能ではありません。
- マイク・スピーカー：「デバイス一覧を更新」で一時的なマイク使用を許可して機器名を取得し、直後に全トラックを停止します。アカウント間でデバイスIDが異なるため、機器名と同名機器の順序を保存し、各セッション内で照合します。同名機器の接続順が変わった場合は選び直してください。「Discord / Windowsの既定」ではDiscord側の選択を使用します。

マイクの変更は次の音声取得から反映し、通話中のマイクを自動で取り替えません。スピーカーは再生中のHTML音声とAudioContextへ適用します。アカウント側にもマイクの使用許可が必要です。指定マイクが見つからない場合は音声取得を失敗させます。スピーカーへの切り替えに失敗した場合は通知し、従来の出力で再生を続けます。フォーカスがない間は、直近で取得した機器の対応を使って通知音の再生待ちを避けます。

音声制御はブラウザ標準APIに限定したページ側の処理で、Node.jsやIPCをDiscordへ公開しません。通知音の判別は現在のDiscord公開配信コードの音声読み込み先に基づきます。Discordの実装変更や別の再生経路では追従が必要になる場合があります。

## 開発・検証

アイコンの元画像は `src/assets/app-icon.png`、Windows用は `src/assets/app-icon.ico` です。元画像は透過を保持して保存しています。ICOを再作成する場合はWindowsのPowerShellで `.\scripts\build-icon.ps1` を実行してください。実行ファイルへのアイコン・製品情報の埋め込みを有効にし、コード署名は無効のままです。

```powershell
npm.cmd run check
npm.cmd test
npm.cmd run test:ui
npm.cmd run test:e2e
npm.cmd run test:live
npm.cmd run dist:win
```

`test:e2e` は一時フォルダとローカルのテスト画面を使い、実際のElectronウィンドウで列操作、モーダルの表示、ネイティブ描画領域、Cookie分離、再起動後の保持、削除時のデータ消去を検証します。実際のDiscordへのログインやメッセージ送信は行いません。

`test:ui` はインストール済みのChromeまたはEdgeで、管理画面のフォームとレイアウトを検証します。Electronの管理APIをテスト用アダプタに差し替えるため、ネイティブ描画・Cookie保持の検証にはなりません。別のChromium系ブラウザを使う場合は `DISCORDDECK_BROWSER` に実行ファイルのパスを指定できます。`npm test` のメイン処理テストもElectron APIのテスト用代替を使って操作・権限の分岐を検証します。

`test:live` は一時プロファイルでDiscord公式Web版を2列開き、未ログインのログイン画面まで表示できるか確認します。認証済みアカウントでの受信・送信・再ログイン保持は、利用者による実機確認が必要です。テスト画像と実機確認結果は `artifacts` に出力します。

ElectronはWebコンテンツを扱うため、利用を続ける場合は定期的に更新してください。自動アップデートは未実装です。
